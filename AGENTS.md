# Правила работы агента

## Навигация

Начни с [docs/PROJECT_MAP.md](docs/PROJECT_MAP.md): выбери задачу и открывай только связанные файлы. Этот репозиторий отвечает за интерфейс; серверные расчёты, права и интеграции находятся в `TeamChaika/team_back` (локально обычно `../chaika-team-backend`). Не путай его со старым `iiko_Collector/backend/frontend`.

При изменении маршрутов, состава модулей или API-связей обновляй карту в той же задаче. Проверяй реальные пути и текущую ветку; карта не заменяет проверку затронутого кода.

## Оценка сложности и делегирование

Перед выполнением оценивай сложность задачи, учитывая неопределённость и последствия ошибки, а не только объём работы.

Используй субагентов для самостоятельных частей работы:

- лёгкие — `gpt-6-luna`;
- средние — `gpt-6-sol`;
- сложные — `gpt-6-astra`.

Если исполнитель не справляется, передавай работу модели следующего уровня вместе с полученными результатами, проверками и оставшимися проблемами: `gpt-6-luna` → `gpt-6-sol` → `gpt-6-astra`.

Коротко сообщай выбранную модель и причину. Для коротких ответов и простых неделимых действий не запускай лишних субагентов.

## API на клиентских доменах

Клиентский кабинет и гостевая оплата используют текущий `window.location.origin`
и `/api` через edge-прокси. Не выводи `api.<домен>` из адреса страницы и не
переключай неизвестный host на API Чайки. Исключения основного dashboard задаются
только точным `VITE_PRIMARY_ORIGINS`; его `VITE_API_BASE_URL` сохраняется.
Платёжный context требует точного совпадения `payment_origin` и `api_origin` с
текущим origin и открывает исключительно гостевые маршруты без cookies/Referer.
