# Chaika Team — Frontend

React + TypeScript + Mantine. Сборка через Vite. Интерфейс аналитики ресторанной сети: обзор, продажи, закупочные цены, накладные, перемещения, списания, номенклатура, техкарты, остатки, сотрудники, события заказов и чат помощника.

Бэкенд находится в отдельном репозитории `TeamChaika/team_back`. Production-сайт `https://dashboard.chaika.team` обращается к API `https://xx.chaika.team/api`. Локально используется `/api`. Реквизиты iiko и PostgreSQL во фронтенде не используются.

Раздел `/indicators` показывает дневные показатели и сравнение со вчерашним днём. Карточки можно скрывать и переставлять; настройки хранятся в этом браузере отдельно для каждого пользователя. Панель фильтров поддерживает несколько ресторанов и дополнительные измерения iiko. Время в пречеке включается в настройках карточек и запрашивается из iiko отдельно, поскольку его нет в архивной выгрузке.

## Установка и сборка

Нужны Node.js 22 LTS и npm. Из корня репозитория:

```sh
npm ci
npm run build
```

Готовый сайт находится в `dist/`. TypeScript проверяется при сборке. `.env.production` содержит только публичный адрес API; `npm run build` и CI используют его автоматически. Переменная `VITE_API_BASE_URL` считывается при сборке, поэтому после изменения адреса нужна новая сборка. Не помещайте секреты в `VITE_*`.

## CI/CD

`.github/workflows/ci.yml` при push в `chaikaiiko`, при pull request и вручную выполняет `npm ci` и `npm run build`. Готовый `dist/` сохраняется артефактом с идентификатором коммита. Сборка не требует рабочих секретов.

Для автоматического развёртывания можно добавить отдельное CD-задание, использующее этот артефакт, после выбора сервера и настройки доступа. Сейчас workflow проверяет и собирает приложение, но не публикует его на сервер.

## Локальный совместный запуск

Разместите папки рядом:

```text
team_back/
team_front/
```

В локальном `.env` бэкенда задайте:

```dotenv
CHAIKA_WEB_FRONTEND_DIR=../team_front/dist
CHAIKA_WEB_ORIGIN=http://127.0.0.1:8013
CHAIKA_WEB_SECURE_COOKIE=false
```

Для локального варианта соберите фронтенд командой `npm run build -- --mode development`: он будет использовать `/api`. Затем запустите `app.portal:app` из папки backend на порту 8013. Сайт и API будут доступны на http://127.0.0.1:8013/.

## Разработка с Vite

```sh
npm run dev -- --port 5173 --strictPort
```

Vite проксирует `/api` на `http://127.0.0.1:8013`. Для этого режима установите в backend `CHAIKA_WEB_ORIGIN=http://127.0.0.1:5173` и перезапустите процесс портала. Открывайте сайт по этому же адресу: проверка Origin защищает вход и выход.

## Публикация на dashboard.chaika.team

1. Соберите `npm ci && npm run build` или скачайте `frontend-dist-<SHA>` из успешного CI.
2. Разместите содержимое `dist/` в `/srv/chaika/team_front/dist` на сервере фронтенда; каталог должен быть доступен пользователю Caddy для чтения.
3. Добавьте блок из [ops/Caddyfile](ops/Caddyfile) к конфигурации Caddy. Он включает HTTPS, fallback React Router, кэширование файлов сборки и разрешение соединений с `xx.chaika.team` в CSP.
4. На backend задайте `CHAIKA_WEB_ORIGIN=https://dashboard.chaika.team` и `CHAIKA_WEB_SECURE_COOKIE=true`. [Полная инструкция backend](https://github.com/TeamChaika/team_back/blob/chaikaiiko/docs/domains.md).

DNS домена должен указывать на сервер фронтенда, порты 80/443 — быть доступны Caddy. На сервере с уже работающим Caddy добавляйте блок, сохраняя существующие сайты. Перед reload проверьте `caddy validate --config /etc/caddy/Caddyfile`.

Все запросы, включая обновление сессии, передают cookies на API. Cookies выдаёт backend: JavaScript не получает токены. `npm run dev` сохраняет локальный proxy-режим; `npm run preview` предназначен только для проверки сборки.

Репозиторий содержит исходники, lock-файл и публичный адрес API. `node_modules`, `dist`, рабочие учётные данные и выгрузки базы в Git не добавляются.
