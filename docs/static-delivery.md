# Сжатие и кеширование frontend в Timeweb

Приложение `254029`, `dashboard.chaika.team`, репозиторий `TeamChaika/team_front`, ветка `chaikaiiko`.

## Где применяется настройка

Активный frontend обслуживает встроенный Caddy в Timeweb App Platform. Файл `ops/Caddyfile` предназначен только для альтернативного собственного VPS и не применяется к текущему приложению.

[ops/timeweb-reverse-proxy.json](../ops/timeweb-reverse-proxy.json) фиксирует тело настройки `reverse_proxy` для `PATCH /api/v1/apps/254029`. Это образец состояния платформы, не файл автоматической настройки при сборке. Перед повторным применением прочитать текущий `reverse_proxy` и сохранить новые правила пользователя; не заменять их этим образцом вслепую. Сохранение настройки запускает деплой приложения.

Настройки:

- `gzip` и `zstd` включены; алгоритм согласуется с браузером через `Accept-Encoding`.
- `Cache-Control: private, no-cache` разрешает браузеру хранить ответ, но требует проверки актуальности. При неизменившемся файле сервер возвращает `304`, тело не скачивается заново. Это не режим кеширования без сетевого запроса.
- SPA fallback включён, чтобы прямой вход на `/purchase-prices`, `/transfers` и другие маршруты открывал приложение.

Timeweb предоставляет глобальные правила заголовков без условия по пути. Поэтому не задавать здесь длительный `max-age` или `immutable`: они затронут также HTML и могут оставить пользователей на старой версии. Длительный кеш только для хешированных `/assets/*` потребует отдельной подтверждённой возможности маршрутизации. Backend `xx.chaika.team` имеет собственные настройки и этим изменением не затрагивается.

## Проверка после применения и после релиза

1. Дождаться успешного конкретного деплоя и проверить его SHA.
2. Взять актуальные имена JS/CSS из HTML. Проверить GET с `Accept-Encoding: gzip` и `zstd`: `Content-Encoding`, `Vary: Accept-Encoding`, `Cache-Control`, реальный размер скачивания. Распакованные файлы должны совпадать с исходной сборкой.
3. Повторить GET с полученным `ETag` в `If-None-Match`: ожидается `304` без тела.
4. Проверить HTML и прямой вход на вложенный маршрут, авторизованную страницу и ошибки браузера. HTML должен требовать перепроверку актуальности.
5. Для замера повторного открытия в DevTools снять `Disable cache`; отдельно измерять первое открытие со скачиванием файлов.

Откат: восстановить сохранённое предыдущее значение `reverse_proxy` в настройках приложения и проверить завершение нового деплоя. До первоначальной настройки 07.10.2026 значение было `null`; это не универсальный шаблон отката для будущих изменений.

Документация платформы: [настройка веб-сервера](https://timeweb.cloud/docs/apps/reverse-proxy).
